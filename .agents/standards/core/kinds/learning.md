# Definition of Done - learning

A learning project is done when the learner can show the skill, not when the material has
been read. This replaces the code bar for projects of kind `learning`.

## For every learning run

- [ ] The goal is stated as something the learner will be able to do, and by when
- [ ] The starting level is recorded, so progress can be seen
- [ ] The plan lists the material in order and why that order
- [ ] Each session is logged in the run's `progress.md`: what was covered, what was hard
- [ ] There is evidence of use: an exercise done, a small thing built, an explanation written
      without looking at the source
- [ ] Gaps found along the way are listed with the next step for each
- [ ] A review is scheduled for what is easy to forget (date in the run or as a reminder task)
- [ ] The run's `handoff.md` says where to resume and what the next session should open with

## Not done

| Claim | Why it is not done |
|---|---|
| "I finished the course" | Completion is not capability; show the exercise |
| "I understand it" | Explain it, or apply it to something the material did not cover |
| "I'll review it later" | Put the date on a reminder (`ws remind`), or it will not happen |
